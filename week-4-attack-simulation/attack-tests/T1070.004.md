# T1070.004 — File Deletion

## Test profile

| Field | Value |
| --- | --- |
| Tactic | Defense Evasion |
| Atomic test | `T1070.004-1` — Delete a Single File |
| Target | `/tmp/victim-files/T1070.004-test.txt` |
| Final result | **COVERAGE GAP** |

## Prerequisite troubleshooting

The first prerequisite check failed because the target file did not exist. Atomic's prerequisite creation behavior initially left the expected file absent, so the file's existence was checked directly and the prerequisite was prepared before retesting.

The final check returned that prerequisites were met.

## Execution

Atomic successfully deleted the file:

```text
Exit code: 0
```

PowerShell validation returned:

```text
Test-Path /tmp/victim-files/T1070.004-test.txt
False
```

This proves the attack action completed.

## Detection result

Wazuh produced no T1070.004 detection. FIM configuration inspection showed monitoring for:

```text
/etc
/usr/bin
/usr/sbin
/boot
```

The deleted test file was under `/tmp`, outside the configured FIM scope.

Suricata was not applicable to this local file operation. No TheHive case was expected without a routed Wazuh alert.

## Final assessment

**COVERAGE GAP.** The missing alert is explained by monitoring scope, not by failed Atomic execution.

## Engineering decision

The lab was not changed solely to make the result green. Broad real-time monitoring of `/tmp` can generate substantial noise. A production-oriented decision should evaluate specific high-risk temporary paths, exclusions, event volume, and the value of process telemetry before expanding FIM coverage.
